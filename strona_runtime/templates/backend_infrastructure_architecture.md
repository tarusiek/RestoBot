# Backend, Database & Multi-Tenant Infrastructure Architecture

This document contains the production-ready architecture for the AI-driven, multi-tenant Restaurant Generation platform. The infrastructure is heavily optimized for edge performance, multi-region scalability, and AI-safe data validation. It is designed to work seamlessly with Next.js App Router, Supabase (PostgreSQL), Prisma ORM, Redis, and Vercel.

---

## 1. Multi-Tenant Database Architecture (PostgreSQL)
The system employs a **Logical Segregation** multi-tenant strategy within a single PostgreSQL database. Every table includes a `tenant_id` foreign key. Supabase Row Level Security (RLS) policies act as the ultimate safeguard, preventing cross-tenant data leakage.

### Prisma Schema Definition (`prisma/schema.prisma`)
The core persistence relies heavily on `JSONB` to store the dynamic, localized UI configurations generated by the AI, maintaining flexibility without massive relational overhead.

```prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

generator client {
  provider = "prisma-client-js"
}

model Tenant {
  id              String           @id @default(uuid())
  slug            String           @unique // e.g., "bistro-warszawa"
  customDomain    String?          @unique // e.g., "bistrowarszawa.pl"
  name            String
  createdAt       DateTime         @default(now())
  updatedAt       DateTime         @updatedAt

  // Relationships
  users           UserTenant[]
  revisions       ConfigRevision[]
  reservations    Reservation[]
  media           MediaAsset[]
  activeConfigId  String?          // Pointer to currently published revision
}

model ConfigRevision {
  id              String   @id @default(uuid())
  tenantId        String
  tenant          Tenant   @relation(fields: [tenantId], references: [id], onDelete: Cascade)
  
  // The full AI-generated, Zod-validated configuration
  configData      Json     // Stores LocalizedStrings (EN/PL), Blocks, ThemeTokens
  
  commitMessage   String?
  publishedAt     DateTime @default(now())
  createdBy       String   // User ID
  isDraft         Boolean  @default(true)

  @@index([tenantId, isDraft])
}

model Reservation {
  id              String   @id @default(uuid())
  tenantId        String
  tenant          Tenant   @relation(fields: [tenantId], references: [id], onDelete: Cascade)
  
  bookingDate     DateTime
  timeSlot        String
  guestCount      Int
  status          String   @default("PENDING") // PENDING, CONFIRMED, CANCELLED
  
  customerName    String
  customerEmail   String
  customerPhone   String
  specialRequests String?  @db.Text
  dietaryTags     String[]
  
  createdAt       DateTime @default(now())
  
  @@index([tenantId, bookingDate])
}

model User {
  id        String       @id @default(uuid()) // Supabase Auth UID
  email     String       @unique
  tenants   UserTenant[]
}

model UserTenant {
  userId    String
  tenantId  String
  role      String       // "OWNER", "MANAGER", "EDITOR", "CHEF"
  
  user      User         @relation(fields: [userId], references: [id], onDelete: Cascade)
  tenant    Tenant       @relation(fields: [tenantId], references: [id], onDelete: Cascade)

  @@id([userId, tenantId])
}
```

## 2. API & Edge Infrastructure Strategy
To guarantee ultra-low latency globally (TTFB < 50ms) and support the high traffic of restaurant websites, the API is split between Edge and Serverless functions.

### Tenant Resolution Middleware (`middleware.ts`)
Executes at the Vercel Edge. Intercepts incoming requests, parses the host header (`bistrowarszawa.pl` or `platform.com/bistro-warszawa`), looks up the `tenantId` from an Edge Redis cache (Upstash), and rewrites the URL to the localized App Router path.

```typescript
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';
import { getTenantByHost } from '@/lib/edge-redis';

export async function middleware(req: NextRequest) {
  const url = req.nextUrl;
  const hostname = req.headers.get('host')!;

  // Edge Redis Lookup (Extremely Fast)
  const tenant = await getTenantByHost(hostname);
  
  if (tenant) {
    // Rewrite to dynamic tenant route, preserving language param
    const lang = url.pathname.split('/')[1] || 'en';
    return NextResponse.rewrite(new URL(`/${lang}/${tenant.slug}${url.pathname}`, req.url));
  }

  return NextResponse.next();
}
```

## 3. Dynamic Config Persistence & AI Validation
Because the system is fully config-driven, the `configData` JSON blob in PostgreSQL dictates the entire frontend (Colors, Content, Sections, Languages). 

### Validation Pipeline:
1. **AI Generation / CMS Edit**: A payload is generated.
2. **Server Action Validation**: Before hitting Prisma, the JSON is strictly validated using the global Zod `RestaurantConfigSchema`.
3. **Persist & Revalidate**: If valid, it is saved as a new `ConfigRevision`. A webhook triggers `revalidateTag(tenantId)` to bust the Next.js Data Cache globally.

```typescript
import { RestaurantConfigSchema } from "@/contracts/System";
import prisma from "@/lib/prisma";
import { revalidateTag } from "next/cache";

export async function publishTenantConfig(tenantId: string, rawJson: any) {
  // 1. AI-Safe Validation Layer
  const validatedConfig = RestaurantConfigSchema.parse(rawJson);

  // 2. Persist to DB
  const revision = await prisma.configRevision.create({
    data: {
      tenantId,
      configData: validatedConfig as any,
      isDraft: false,
      commitMessage: "Published via API",
    }
  });

  // 3. Update active pointer
  await prisma.tenant.update({
    where: { id: tenantId },
    data: { activeConfigId: revision.id }
  });

  // 4. Bust global CDN Cache
  revalidateTag(`tenant-${tenantId}`);
}
```

## 4. AI Generation Pipeline & Queue System
AI tasks (like generating an entire localized restaurant configuration from a 2-sentence prompt) take time. They cannot be run synchronously in standard serverless functions due to timeout limits.

### Architecture (Inngest / Upstash QStash):
- **Event-Driven**: The admin triggers an event: `ai.generate.website`.
- **Background Worker**: A dedicated background process spins up. It orchestrates multiple LLM calls (e.g., Gemini):
  1. Generate Brand Identity & Theme Tokens.
  2. Generate Polish Copy.
  3. Translate Polish to English.
  4. Generate standard UI blocks.
- **WebSocket / Server-Sent Events (SSE)**: The background worker streams progress back to the CMS UI ("Generating Menu...", "Translating to English...").

---

## 5. Reservation & Event Architecture
Handles bookings dynamically, supporting waitlists and external routing.

- **Optimistic Concurrency Control**: Prevents double-booking a time slot using database-level locking.
- **Webhook Integrations**: If the config uses OpenTable, the API proxy transforms the payload and pushes it. If internal, it hits the Supabase database.
- **Transactional Emails (Resend)**: Upon `Reservation` creation, a database trigger or background job fires an email template via Resend to the customer (`reservation-confirmed.html`) and SMS/Email to the restaurant manager.

---

## 6. Media Storage Architecture (AWS S3 / Supabase Storage)
- Assets uploaded via the CMS are pushed directly to S3-compatible storage.
- **Dynamic Image Optimization**: The Next.js `<Image>` component acts as the CDN proxy, converting original S3 uploads into WebP/AVIF and resizing them based on viewport context.
- **AI Media Tagging**: Background workers analyze uploaded images to generate SEO-friendly `alt` text in multiple languages.

---

## 7. Security, Authorization, and Rate Limiting
- **Supabase RLS**: Even if an API endpoint has a vulnerability, PostgreSQL RLS prevents `User A` from reading `Tenant B`'s reservations.
- **Rate Limiting (Redis)**: Endpoints like `/api/booking` or `/api/newsletter` are strictly rate-limited using Upstash Redis sliding window algorithms to prevent spam/DDoS.
- **Cloudflare Turnstile**: Integrated on all public forms (Reservations, Contact, Newsletter) to block bots without CAPTCHA friction.

---

## 8. Multi-Region Scaling Strategy
As the platform expands globally:
1. **Database Read Replicas**: Supabase read replicas deployed in the EU (for Polish restaurants) and US (for global expansion).
2. **Next.js Edge Caching**: Pages are statically generated (SSG/ISR). Vercel's Edge Network serves the HTML from the node closest to the user.
3. **Asset CDN**: Cloudflare caches all CSS, JS, and Media assets globally.

---

## 9. Analytics & Event Tracking Architecture
A privacy-first analytics pipeline.
- **Event Tracking**: Clicks on "Book Table" or "Call Now" are sent to a lightweight edge endpoint (`/api/track`).
- **Data Warehouse**: Events are pushed to a time-series database (e.g., ClickHouse or Tinybird) for aggregation.
- **Admin Dashboard**: The CMS polls this aggregated data to display conversion rates and visitor metrics in real-time, completely bypassing heavy third-party scripts like Google Analytics if GDPR compliance is strictly preferred.
